Eje Metodológico 01

Tema N°1: ¿Cuál es la Idea de Trabajo Principal?

Digitalización, trazabilidad espacial y eliminación de asimetrías de información en nichos gastronómicos locales.

Propósito Integral de SLUSH

El proyecto integrador SLUSH resuelve la dispersión de información sobre los puntos de venta de granizados tradicionales y frappés de autor en el Valle de Aburrá. Mientras los directorios genéricos limitan sus atributos a nombres y horarios, SLUSH introduce métricas especializadas: tipo de base (frutal al agua, cremosa con adición láctea, michelada/ácida o combinada con licor), volumen volumétrico en onzas, nivel de aforo en tiempo real y correlación meteorológica.

  • Para el Usuario: Localización precisa, cálculo de tiempo de desplazamiento y visualización previa de carta y aforo.
  • Para el Negocio: Plataforma de exposición equitativa sin aranceles de intermediación, con métricas territoriales de venta.

Arquitectura Desacoplada en Tres Capas

La solución se fundamenta en una separación estricta de responsabilidades que garantiza portabilidad, seguridad perimetral y soporte a concurrencia masiva:

  • Capa de Persistencia (SQL Server): Integridad referencial reforzada, tablas normalizadas, procedimientos transaccionales y disparadores DML.
  • Capa de Lógica Algorítmica (Java POO / Microservicios): Modelado orientado a objetos con control contable, nómina, inventario y ruteo seguro.
  • Capa de Presentación (Frontend SPA): Interfaz modular en HTML5 semántico, variables CSS personalizadas y motor interactivo en JavaScript ES6+.

5. Disparador (Trigger): Recálculo Atómico de Calificación Promedio
Explicación:

Soluciona el compromiso entre normalización pura y eficiencia computacional. Ejecutar funciones de agregación AVG() mediante JOIN en cada petición del mapa colapsaría el rendimiento de I/O en disco. Este disparador DML intercepta eventos AFTER INSERT, UPDATE, DELETE sobre Resenas, extrae los locales modificados desde las tablas virtuales del sistema (inserted y deleted) y recalcula atómicamente el promedio ponderado, almacenándolo de forma materializada en la tabla Locales.

T-SQL: Disparador DML de Rendimiento 
CREATE TRIGGER TRG_Actualizar_Calificacion_Local
ON Resenas
AFTER INSERT, UPDATE, DELETE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @LocalesAfectados TABLE (local_id INT);

    INSERT INTO @LocalesAfectados
    SELECT DISTINCT local_id FROM inserted
    UNION
    SELECT DISTINCT local_id FROM deleted;

    UPDATE L
    SET L.calificacion_promedio = ISNULL(Sub.Promedio, 0.00)
    FROM Locales L
    INNER JOIN @LocalesAfectados A ON L.local_id = A.local_id
    OUTER APPLY (
        SELECT CAST(AVG(R.calificacion) AS DECIMAL(3,2)) AS Promedio
        FROM Resenas R
        WHERE R.local_id = L.local_id
    ) Sub;
END;
GO
6. Procedimiento Almacenado: Registro Seguro y Validación RN-02 (Ventana 24h)
Explicación:

Encapsula la lógica de inserción de reseñas dentro de una transacción explícita bajo propiedades ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad). Valida formalmente la regla de negocio RN-02 mediante la función DATEADD(HOUR, -24, SYSDATETIME()). Si el usuario ya emitió una evaluación sobre ese mismo establecimiento en las últimas 24 horas, la transacción se aborta con ROLLBACK y retorna el código HTTP 400. En caso de éxito, confirma con COMMIT retornando el código 200.

T-SQL: Stored Procedure Transaccional 
CREATE OR ALTER PROCEDURE USP_RegistrarResena
    @local_id INT,
    @usuario_id INT,
    @calificacion DECIMAL(2,1),
    @comentario NVARCHAR(MAX),
    @origen_plataforma VARCHAR(30) = 'SLUSH_Direct',
    @Mensaje VARCHAR(250) OUTPUT,
    @CodigoEstado INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    BEGIN TRY
        BEGIN TRANSACTION;

        IF EXISTS (
            SELECT 1 FROM Resenas 
            WHERE local_id = @local_id 
              AND usuario_id = @usuario_id 
              AND fecha_resena >= DATEADD(HOUR, -24, SYSDATETIME())
        )
        BEGIN
            SET @CodigoEstado = 400;
            SET @Mensaje = 'Violación RN-02: Ya has calificado este punto de venta en las últimas 24 horas.';
            ROLLBACK TRANSACTION;
            RETURN;
        END

        INSERT INTO Resenas (local_id, usuario_id, calificacion, comentario, origen_plataforma)
        VALUES (@local_id, @usuario_id, @calificacion, @comentario, @origen_plataforma);

        COMMIT TRANSACTION;
        SET @CodigoEstado = 200;
        SET @Mensaje = 'Reseña registrada con éxito. Promedio recalculado vía Trigger.';
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 
            ROLLBACK TRANSACTION;

        SET @CodigoEstado = 500;
        SET @Mensaje = 'Fallo de motor SQL Server: ' + ERROR_MESSAGE();
    END CATCH
END;
GO

Explicación:

La regla de negocio RN-06 limita el peso de las imágenes a 5120 KB mediante una restricción CHECK[cite: 34, 37]. En esta consulta utilizamos ISNULL() para manejar reseñas sin evidencia y concatenamos el sufijo 'KB' para la auditoría de almacenamiento[cite: 34].

T-SQL EJECUTADO EN SSMS (LÍNEAS 305 – 320) 
SELECT 
    R.resena_id AS [ID Reseña],
    L.nombre_local AS [Local],
    U.nombre_completo AS [Cliente],
    U.correo AS [Correo Cliente],
    R.calificacion AS [Puntaje],
    R.comentario AS [Comentario],
    R.origen_plataforma AS [Origen],

    R.nombre_rol AS [Rol en Plataforma],
    ISNULL(U.telefono, 'No registrado') AS [Teléfono],
    FORMAT(U.fecha_registro, 'yyyy-MM-dd HH:mm') AS [Fecha Alta]
FROM Usuarios U
INNER JOIN Roles R ON U.rol_id = R.rol_id
ORDER BY R.rol_id, U.nombre_completo;
Evidencia 6/10 — Vistas Relacionales

Vistas Multitabla para Roles y Propietarios

Creación de `vw_Roles_Multitabla_1` y `vw_Roles_Multitabla_2`, abstrayendo las uniones entre roles, usuarios y los locales que administran[cite: 7, 21].

Explicación:

Encapsulamos la complejidad relacional mediante vistas de SQL Server[cite: 7, 21]. La vista multitabla 2 cruza tres niveles de entidad para exponer directamente al comerciante con su local asignado (ej. Propietario Ilícito y Propietario Siglo 22)[cite: 21].

T-SQL EJECUTADO EN SSMS 
CREATE VIEW vw_Roles_Multitabla_2 AS
SELECT 
    r.nombre_rol,
    u.nombre_completo AS [Comerciante],
    l.nombre_local,
    l.direccion
FROM Roles r
INNER JOIN Usuarios u ON r.rol_id = u.rol_id
INNER JOIN Locales l ON u.usuario_id = l.usuario_dueno_id;
GO
Evidencia 7/10 — Subconsultas

Subconsultas Correlacionadas con Cláusula IN

Auditoría de asignación activa mediante la vista `vw_Roles_Subconsulta_1` que filtra roles asociados a cuentas de usuario reales[cite: 19, 20].

Explicación:

Implementamos subconsultas con operadores de pertenencia IN (SELECT DISTINCT rol_id FROM Usuarios) para optimizar el plan de ejecución y evitar combinaciones redundantes en lecturas frecuentes[cite: 20].

T-SQL EJECUTADO EN SSMS 
CREATE VIEW vw_Roles_Subconsulta_1 AS
SELECT rol_id, nombre_rol
FROM Roles
WHERE rol_id IN (SELECT DISTINCT rol_id FROM Usuarios);
GO
Evidencia 8/10 — Clima & Sensación Térmica

Vistas de Sectores y Parámetros Meteorológicos

Vista `vw_Sectores_Multitabla_2` que integra los sectores, los puntos comerciales y la sensación térmica calculada para cada zona urbana[cite: 11, 12].

Explicación:

Esta vista permite que el frontend obtenga en una sola llamada el sector, municipio, nombre comercial y la sensación térmica en grados Celsius sin recalcular uniones pesadas en el servidor web[cite: 11, 12].

T-SQL EJECUTADO EN SSMS 
CREATE VIEW vw_Sectores_Multitabla_2 AS
SELECT 
    s.nombre_sector,
    s.municipio,
    l.nombre_local,
    c.sensacion_termica_c
FROM Sectores s
INNER JOIN Locales l ON s.sector_id = l.sector_id
INNER JOIN ClimaSectores c ON s.sector_id = c.sector_id;
GO
Evidencia 9/10 — Filtro de Demanda

Sectores con Demanda Alta Indexada

Subconsulta que aísla los sectores que actualmente registran puntos comerciales en estado 'Alta' demanda para priorizar la distribución logística[cite: 9, 10].

Explicación:

Con la vista vw_Sectores_Subconsulta_1 identificamos los sectores críticos con alta rotación de clientes (como El Poblado, Laureles y Belén) para activar las alertas de aforo en el mapa interactivo[cite: 9, 10].

T-SQL EJECUTADO EN SSMS 
CREATE VIEW vw_Sectores_Subconsulta_1 AS
SELECT sector_id, nombre_sector, municipio
FROM Sectores
WHERE sector_id IN (
    SELECT sector_id FROM Locales WHERE nivel_demanda = 'Alta'
);
GO
